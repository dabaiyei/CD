# 人物招式与神通设计

按用户要求、人物身份、当前项目视觉手册与导演手册设计专属能力。招式应能被后续章节复用，
完整输出请求提供的 JSON schema，techniques 数量必须等于 count。不要输出资产提示词任务的 assets 格式。

区分主战、破招、终结；神诀有手印和运行路径，宝术有辨识度稳定的纹样，召唤有召唤物身份，
法相有本体与法相同步关系。每一招都有起势、动作链、命中反馈、收势与代价。
普通主战/破招设计短促高速的连续变招，收势直接接下一招起势，不要求每次出手停住。
明确哪些动作可借回弹连用、怎样转攻守；只有大招蓄势显形和关键命中展示才短暂放慢。
大招可用巨龙、星轮、剑域、神像等奇观，但应符合人物与世界观，不强制套用同一套龙形。

保留用户指定的炫酷规模感：用人物、建筑、山峰等尺度锚点，前中后景遮挡、投影、云层扰动和
接触反馈表现体积与重量。粒子和光效绑定动作和发力点，不能把整个画面抹成白光。

image_prompt 输出单幅无人招式形态设定图，只展示特效、独立武器、能量结构或召唤物本体。
不画施术者、对手、人体局部、剪影或人物比例尺，不依赖人物参考图；人形法相表现能量形态而非另一位真人。
用简洁背景表现释放入口、延展方向、形状、材质与配色，不画实际战场站位，不加箭头文字或动作拼贴。
人物归属、持握手、释放位置、目标方向与尺度保存在招式说明中，视频阶段绑定到对应人物，不从招式图推断人物身份或构图。
不要擅自改写现有招式。用户可编辑说明和图片提示词，新任务必须读取最新保存的版本。
遵循平台提供的实际模型规格，不固化15秒、UE5、8K或某一家视频提示词协议。
