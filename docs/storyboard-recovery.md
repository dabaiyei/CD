# 分镜生成、审核与断点恢复

生成和审核均以小批次提交，章节分镜只有在所有批次完成且通过结构校验后才发布。中间结果保存在任务请求的断点数据中，不把半份分镜当作正式版本。

## 批次资料隔离与格式修复

生成批次的 Runtime 工作区不再挂载整章原稿、生效剧本、旧分镜和整份任务输入。
平台从完整任务输入（包括分页文件）保留模型能力及输出契约，再交付当前源段、必要衔接信息与局部操作文件。
本批未引用资产不重复携带生图长提示词；身份描述/名称索引保留，相关资产及父资产仍提供参考。
阶段规则和所选手册继续按需检索，不把所有技能强行内联到上下文。

分镜返回格式修复使用单次无工具请求，只提供已有输出、结构契约、合法时间槽及恢复截断末镜所需的本批原文。
清除历史、技能、附件及项目文件，使用既有 `storyboard_patch_reasoning_effort` 设置。
已能解析的完整镜头由代码保留，不能被格式校正改写；截断末镜也不能被直接删掉以凑成合法JSON。
无依据或仍不完整的结果不会发布，既有批次断点继续生效。

`storyboard_generation.state.call_diagnostics` 按调用标签保存 `finish_reason`、返回字符数、工具模式和配置的输出 token 上限。
供应商明确返回 `length/incomplete` 时进度会说明；即便标为正常结束，仍执行结构完整性检查。
未配置上限时采用供应商默认值，不能仅凭字符数断言 token 耗尽，也不会擅自抬高所有模型的参数。
可用 `scripts/probe_storyboard_format.py <task_id>` 对一个已存镜头执行付费格式探针；不修改任务、剧本或分镜，验证一次模型调用和字段保留。

## 首帧模式

项目设置中的「首帧模式」默认关闭：分镜不建立前镜视频依赖，视频可独立生成。人物身份、站位、轴线、持物、动作进出状态及不重复邻镜内容的要求仍生效；长连招尽量放在同一视频片段的内部切镜中。

开启首帧模式需要项目视频模型明确支持 `first_frame`、单张图片输入及 PNG/JPEG/WebP 格式；只有同一非空 `continuity_group` 的相邻镜头等待前镜，并使用前镜实际尾帧。相同场景或相同人物本身不会触发等待；空分组、换组或独立新机位照常独立生成。关闭开关后，尚未提交供应商的尾帧等待任务会解除依赖；已提交的请求按原请求完成。旧分镜不会自动重写，新分镜按当前设置规划；若希望旧分镜重新设计接续方式，可修复或重做对应分镜及提示词。

分镜生成、审核、修复、视频提示词和独立打斗设计共享项目执行策略，禁止关闭模式时又因旧手册要求引入尾帧依赖。人物及镜头稳定性仍受生成模型能力影响，执行约束不能保证每次画面完全一致。

## 有限并发加速

- 分镜生成最多两路：提前生成下一批，按原始顺序校验、编号和保存。固定场景边界和时长计划，并提供有限的前后场景上下文；同场景拆分和连续打斗保持顺序生成。
- 视频提示词最多三镜并行，每镜独立校验、提交、记录版本；失败镜头单独重试，已保存镜头不重做。打斗、表情、对白、参考图和音频约束继续生效。
- 分镜审核默认四路，可通过 `STORYBOARD_REVIEW_CONCURRENCY` 设置为 1–8 路；Runtime 的 `AGENT_RUNTIME_MAX_CONCURRENT_RUNS` 默认四路。以上并发共同受管理后台对应供应商的并发上限约束；额度不足自动减小并发。运行任务在数据库预留额度，跨 worker 也计入同一额度。
- 审核推理强度独立配置 `STORYBOARD_REVIEW_REASONING_EFFORT`，默认 `low`，也可设 `medium`、`high` 或 `inherit` 沿用模型设置；只对已经启用推理的审核调用生效，不打开原本关闭的推理，不修改创作模型配置，也不丢弃已保存的相同证据审核结论。
- 单镜字段补丁对应 `STORYBOARD_PATCH_REASONING_EFFORT`，选项同上、默认 `low`。只影响按既定审核意见编辑字段的直接调用，剧本、分镜创作和完整重写沿用原模型配置。
- Runtime 的无工具直接调用只允许一次模型推理，外层负责有限重试；不再把仅思考、无正文的回复交给内部 30 轮循环。Responses 中转只返回最终完整正文时会补齐缺失的文字增量；明确未完成或截断的响应直接报出原因，不当作审核通过。
- 审核由服务端准备当前单镜、对应源段、相邻证据、关联资产及本阶段已选规则，模型关闭工具调用，直接返回审核 JSON。每份证据包最多 38000 字符，预留错误提示空间后总输入不超过 40000 字符。超长证据拆为多份直接核验，不再静默回退到多轮工具 Agent；共同的目标镜头、源段与平台规则保留，补充证据不截断。极端超长字段按显式原文分片提供，禁止把分片外内容判为缺失。
- 每份证据包独立保存结论与原始响应。断线、重启或其它包失败后，仅继续未完成包；格式修复只处理该包已返回的结论，全部证据核验完才汇总该镜审核结果。
- 未匹配剧本源段只做一次叙事覆盖检查，不再对每个候选镜头重复同一检查；提供候选镜头完整叙事字段，视觉手册不参与该专项检查，各镜的视觉与资产规则仍由单镜审核负责。
- 单批每次调用最多 300 秒，最多三次尝试，不再叠加传输层三次重试。等待时每 30 秒记录当前阶段、耗时、模型轮数与工具次数；失败显示具体原因，仅重试该批，成功立即保存断点。超时、解析失败等诊断保存在 `attempt_errors`，该批成功后清除。
- 每次模型调用使用独立的临时工作目录，避免并发覆盖文件。保存任务断点的事务保持短小、同一任务串行提交，不在等待模型时占用写事务。
- 遇到限流、网络超时或网关暂时故障，当前任务降至一路并有限退避重试；审核 JSON 格式错误只影响本镜，不降低其它审核的并发。恢复时继续复用已完成批次，不以速度替代完整性审核。等待日志区分 Runtime 执行额度排队与模型响应。
- 审核缓存只依赖本镜、对照镜头、关联资产（包括主资产）、规则与模型；无关资产修改不会使整章缓存失效。旧缓存只有在完整旧指纹仍一致时迁移复用。仅 minor 建议保留展示，不触发自动修复循环。
- 实际速度受供应商额度、响应时间和场景依赖影响；供应商仅允许一路或连续打斗需要串行时，不承诺倍速。

## 保存、审核与修复

剧本审核也使用有界调用：完整任务与规则能放入 48000 字符预算时直接输出结论，额外参考按包提供并逐包保存，不重复附加章节副本。超长原文仍保留分页检索而不截断内容。每次调用最多 300 秒、每 30 秒报告活动、最多三次尝试；格式错误优先修已有结论，空正文可切换直接输出。重启复用同一任务中指纹匹配的证据包，严重问题不能被标成通过。手动停止的流程不会因此自动恢复。

- 有原始时间轴时先按视频模型合法时长分配视频片段，每批最多四个片段；片段内仍可保留多个短镜头。
- 无完整时间轴时按场景和正文长度分批，保留上一镜作为衔接。批次边界保存到断点，恢复时不重新划分。
- 每批最多尝试三次。格式错误先修格式，单镜字段不合法只修该镜，缺镜或预算超限只重新处理当前批。完整剧本、全章分镜不会反复发送。
- 单镜结构修复每次执行最多调用三次，耗尽后不再由外层批次循环放大次数。每次字段补丁合并后保存中间结果，断线或重启后基于最新补丁继续；已通过的前后镜头保留。平台按校验器定位的字段合并，模型返回完整镜头也不能覆盖原本正确的台词和动作。
- 修复使用明确的镜号和字段补丁；严重问题也不默认重写整章。旧审核意见仍支持文字镜号解析，对照镜号不作为修改对象。
- 机位、姿态、持物等空间事实修复允许同步本镜构图、首帧、场景和动作中的同一事实，避免只改一个字段造成下一轮自相矛盾；时长修复允许同步本镜动作、表情、战斗和内部镜头时间轴。未点名的台词与剧情不得改写，其它镜头仍保持不变。
- 文字局部修复优先返回 `edits`（field/old/new）精确替换，原句必须唯一匹配，多处替换需显式 `replace_all`。关联镜头以当前已保存状态为准，避免沿用旧审核引用。补丁合并后检查动作文字时间轴不得超出片段时长，失败只重试本镜。
- 已返回补丁若原句匹配或结构校验失败，保存原始补丁；下次只发送补丁、具体错误与涉及字段的准确原文做校正，不重新发送邻镜和整份设计材料。成功合并后清除该原始补丁断点。
- 审核明确要求把过载镜头拆开时，非固定原始时间轴的镜头可局部拆镜；原对白与动作只分配一次，同步调整新片段表情、战斗与首帧，其它镜头不重写。不能通过强行加速对白来绕过模型时长上限。
- 自动修复只处理 blocking/major，minor 留作建议；用户手动指定修复仍可处理 minor。重启时保留已保存补丁，不因缩小待修复范围撤销或重做旧成果。定点补丁提供本镜、局部源段、邻镜、相关资产、平台规则及模型契约，不重复加载完整创作手册。修复直传上限为 50000 字符（审核证据包仍为 38000），禁止把整章输入直接塞入单镜请求；证据不足或超预算时才使用检索，且同样受 300 秒单次超时约束并显示模型/工具进度。补丁校验失败展示具体原因，只重试该镜。
- Responses 补丁调用若只返回思考、没有正文，下一次本镜尝试显式使用 `reasoning.effort=none`，不改变其它镜头、创作或审核模型配置，也不扩大重试次数；补丁仍须通过结构、时间轴和内容复审。
- Responses 审核证据包同样处理空正文：仅失败包下一次尝试使用 `reasoning.effort=none`，该状态存入断点，已完成包不重跑；输出仍经过完整审核契约校验。
- 完成的场景单独保存。前一批补镜导致镜号变化时，后续已完成场景只重新编号，不重新生成。
- 定点补镜在发布整版时同步重映射动作、首帧、构图、表情和战斗字段中的显式镜号引用；不改台词或资产名称。断点保留旧编号，重启再次组装不会二次偏移。
- 生产审核按单镜保存，默认四路并发，并受 Runtime 总并发限制。单镜证据过长时无损分包直接核验；前后镜头和相关资产的历史状态提供只读对照。
- 审核批次相互独立，孤立批次持续失败后其它批次继续完成并存档，结束后报告失败；继续时只处理未完成批次。连续两批耗尽重试则停止新增调度，避免平台整体离线时逐批浪费调用；在途批次仍可存档。用户取消、上下文失效或存储异常仍中断调度。
- 审核响应格式错误会保存原始结果，优先只发送原结果进行 JSON 格式修复，不重复发送分镜、手册和历史记忆。镜号范围错误或缺少实质问题须带本批证据重新审核；格式修复不能删除可恢复的审核问题或降低其严重程度。
- 审核结果指纹包含实际输入、规则、模型和相邻上下文。修复后复用未受影响批次；镜头、手册或模型改变时重新审核对应内容。
- 所选手册、模型能力、资产绑定、原始中文台词、打斗与表情时间轴、构图和内部切镜字段仍参与生成和校验。最终视频提示词仍在审核通过后单独生成。
- 审核明确区分分镜规划与最终视频提示词：不因空 `video_prompt` 或尚未展开详细逐招编排而报错。审核规则改变时缓存按原有指纹机制失效，不能为复用旧缓存而跳过新规则。
- 参考资产的静态姿势不冻结后续动作，未描述的细节不等于明确不存在；身份、服装、伤势和同一时点的互斥状态仍须核验。关联资产目录数量不等于实际上传图片数，实际参考按媒体去重和模型能力组装。对白与动作可以并行，时长审核区分硬越界与主观节奏建议，禁止机械累加并行时长。
- 无工具、无附件、临时上下文的 Responses 审核/补丁请求使用单次流式传输，不进入 Agent 工具循环；必须收到完整结束和有效正文。其它有工具、记忆或附件的对话继续使用原有运行路径。
- 前一个修复使邻镜问题已消失时，允许返回带具体理由的 `unchanged`，不得同时夹带修改。保留原镜后仍交给审核验证，不能借此把未解决问题标为通过。

全自动任务不再因任务级尝试次数耗尽而停止，每轮继承此前断点，不重建整版。图片生成按工作流记录连续失败次数，成功一张清零，连续失败5次停止全自动并取消其余在途/排队子任务、按原规则退款。其它任务不清零图片计数。手动流程仍保留原尝试上限；单次请求超时、手动停止与积分不足处理不变。

旧版已完成分镜、但尚在提取资产的任务：草稿必须与逐镜存档完全一致，并重新通过当前模型时长与原始时间轴校验，才允许复用。新版断点不会借此绕过输入变更校验。

打斗、表情和内部切镜时间轴在逐镜保存前校验。旧草稿发现表情超时等字段问题时，仅补丁修复出错镜头；只修改表情时间轴不会重复已经完成的资产提取批次。

定点审核修复同样使用最多两个模型槽位，空闲槽位立即接下一个独立镜头，不等待同组慢镜头。相邻镜头和同一审核问题涉及的镜头依次处理；独立镜头并行，单镜失败后保留其它独立镜头结果，相关镜头等待恢复。模型未输出正文仅重试本镜，不将运行时“停止内部重复调用”误判为用户停止任务。未改变视觉内容的台词、表情、时长等补丁复用资产绑定；仅实际变化的视觉内容重新提取资产，保留用户选择的参考图。

自动局部审核修复遵循现有资产目录：修复后绑定的名称均已存在时，直接校验并保留，不重新提取、不补回已移除的基础资产、不覆盖选定衍生版本；只有出现未知资产名称的镜头继续提取。新分镜、完整重做与用户手动创作仍按原有规则提取衍生资产。

无固定原始时间轴时，明确要求补镜的审核意见允许返回 `insert_after` 新镜头，新增镜头逐一校验模型时长、动作/表情时间轴及章节预算，并随修复断点保存。最终统一编号，后续旧镜头不重写。有固定原始时间轴时保持原片段时间窗，不能借补镜扩大原文总时长。

全自动审核取消三轮停滞、12轮上限和剧本5版本放行规则，有严重问题时持续定点修复，不因次数而停止或跳过审核。直接审核包预算为48000字符，减少重复传入规则的分包调用；同镜同字段的重复缺失报告合并，保留全部证据、建议和最高严重程度。审核缓存也可从章节工作流恢复，清理动态中心任务记录不会直接丢失已保存的审核结果。

审核进展及问题签名仍保存用于诊断，但不再作为停止全自动的条件。

定点修复调度同时检查正在运行及尚未运行的前置关联镜头：例如20→21→22不得在20运行时跳过等待中的21而提前启动22。不相邻且没有共同审核问题的镜头仍可并发。审核以中文明确要求延长或重分配时长时，允许同步修改合法时长字段；缺失动作的修复不能仅修改标题/场景而保持动作描述逐字不变，此类空修复在本镜补丁阶段直接反馈，不等整轮复审再发现。

重复场景的源段匹配只是检索候选，不能当成镜头归属。审核与定点修复都提供候选段及前后各一段原文（最多三个有界分段），按具体动作、发生顺序与结果确定实际节拍；涉及数量或剧情结果的主要问题需引用源段 key、原句及本镜冲突。避免将上一场结尾状态套给下一场，并在多轮中反复改回。直接审核、分包审核和检索文件使用同一证据窗口，缓存按实际证据变化失效，不删除已保存分镜。`scripts/probe_review_source_context.py TASK_ID SHOT_INDEX` 可对仍在运行的任务做一次不写入审核结果的真实单镜验证。

Worker 完成回调与恢复巡检可能同时处理同一个已完成子任务。推进前先以数据库事务锁定所属工作流，再读取子任务状态；下一步入队和完成标记一起提交或回滚，避免重复审核、并行修复同一版本及版本切换误报。该锁兼容 SQLite，不能用 SQLite 不生效的 `FOR UPDATE` 替代。迟到的启动通知也不能把已完成子任务改回运行中。并发回归见 `test_director_transition_race.py`。

上述保护作用于所有导演工作流，不按章节或项目特判。公共 Worker 的领取、归属校验和过期恢复也使用 SQLite 可生效的事务写锁；未绑定模型的任务同样不能重复领取。恢复时在锁内重新校验状态和租约，防止把已完成或已续租任务重新排队；流程巡检锁定并刷新工作流后才更新指针，保留新阶段及用户停止状态。并发回归见 `test_task_lifecycle_race.py`，涵盖分镜审核、视频提示词、对话以及无模型任务。上游结果未知的媒体任务仍不盲目重发，实际问题持续不收敛时也仍保留人工处理出口。

跨镜审核问题按真实修改目标汇总：主审镜头、已提供的邻镜/资产沿革证据以及覆盖核验候选镜头均可成为问题目标。发现邻镜错误不再因批次归属不同而重审；保留原镜号、证据、严重程度和修复字段，统一去重后交给定点修复。未提供证据、越界或未定位的问题仍拒绝；不能猜测目标、删除问题或将拒绝结论改为通过。该规则同时用于实时返回、已保存审核和旧的原始返回恢复，不失效已有成功批次。

# 分镜输入预算与重复重试

JEV 临时网络/TLS 连接故障、响应超时与 HTTP 408/425/500/502/503/504 会保留任务断点，等待 30 秒后自动重新入队；429 限流等待 45 秒。等待期间保留任务进度、取消监听和租约心跳，不标记失败或退款。连接建立前的失败最多短暂重试两次，已发送的推理不在传输层重复发送。鉴权、配置、响应契约错误及语义不确定仍按原规则处理，不切换判断模型。

审核恢复先验证并加载全部匹配的已保存结论，显示“已恢复 X/N 批，仅继续剩余 Y 批”，仅未完成或输入已变化的批次进入模型调度。已通过结论仍须匹配本镜、关联证据、规则及模型指纹，不能因恢复而绕过审核。

AI 全自动分镜审核采用增量闸门：自动审核按批串行执行，发现 blocking/major 问题后立即暂停后续批次，先将当前问题交给单镜局部修复，再只复核修复镜头及受影响的相邻镜头。未受影响批次的审核缓存随修复任务传递，并按输入指纹复用；因此不会每修一个问题就从第 1 批重新审核整章。手动发起的完整审核仍可使用受限并发跑完全部批次。

分镜生成与分镜修复的单批本地输入预算为 **200000 字符**。平台保留本批完整原文、已保存镜头、审核结果和硬约束；超过该预算才会明确报错，不会为了凑预算静默删除原文。这个数值是本地请求组装上限，实际供应商仍可能有更低的模型上下文限制。

单镜修复中，JEV 对关联字段的低置信度不再阻断已明确的审核修复。
已确定的 edit/keep 结果保留，仅将未确定字段交给当前单镜补丁请求核验；
没有同一事实的直接矛盾就不修改，写入边界仍限定在原有关联字段集合内。
检查点记录 `jev_repair_deferred_fields`，模型接口或配置故障仍明确报错，不当作语义不确定。

资料导航索引按本批相关性筛选，最多 2400 字符，不再重复发送全部手册预览。
原文分页按稳定 source_ids 顺序读取最多约 2400 字符的窗口，正文只发送一次；
所有原文仍保存在覆盖检查点中，后续分页继续，不能把窗口外的内容算作已完成。
模型能力与硬约束保持原文，资料摘录使用剩余预算。

发送前确定的输入预算错误使用 `[storyboard_input_budget]` 标识，不执行相同的本批重试，
全自动进入可恢复的输入调整状态，保留已完成成果，调整后继续未完成步骤。
这不是通用重试次数上限；其他可重试任务及图片连续五次失败策略保持不变。
