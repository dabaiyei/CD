# JEV 判断控制

首页对话、项目 AI 助手和项目全自动共用管理页 `/admin/jev` 的平台、模型与凭据配置。关闭后使用原流程。

| 入口 | JEV 控制范围 |
| --- | --- |
| 首页普通对话 | 文本/图片/视频分流、参考图选择、续接与自动执行意图；视频提示词创作规则启用及模块选择 |
| 项目 AI 对话 | 讨论/创建/修改/继续；讨论为只读；受托撰写视频提示词时共用首页模块选择 |
| 项目全自动或手动生成任务 | 视频提示词的打斗/表情/行走/语速选择、单镜内部一致性检查、定点修复字段范围 |

JEV 决定有限选项，代码校验并执行；内容生成模型不重复选择这些选项。首页生产路由直接调用所配置 JEV，不再优先尝试 Laya；Laya 评测代码保留。明确原样提交及已确认连续任务沿用冻结提示词，不为重新分类而改写。

项目消息接口的资产提示词、生图、分镜制作、视频提示词及视频生成快捷入口也先经过 JEV，不再凭关键词绕过控制。已选定的任务使用原通道执行，镜号选择、缺失项补全和排队校验仍保留。入口判断随任务保存，助手不重复判断。编辑历史消息时，后面将被删除的回复不能作为授权证据。

快捷任务类别不确定时，只允许再用 JEV 核实是否明确为只读讨论；只有高置信度的 discuss 可以继续文字回答，其它结果仍待确认。这个收窄不会批准写操作，也不会转给创作模型决定。

项目助手的创建/修改/继续可能重叠，例如“修复脚本后提交重审”属于修改，内部创建审核任务不改变用户的操作性质。细分类不确定时，先以**仅本轮原文**让 JEV 判断是否在提问；高置信度提问可只读回答，避免旧的生图指令污染“需要补充什么”等澄清。这个局部判断绝不授权写入。如果不是明确提问，再由 JEV 根据完整局部历史判断 `discuss/execute/unknown` 授权范围；`execute` 仅代表执行本轮指定操作，不扩大到被否定或未来计划中的动作，原有平台校验仍照常执行。所有判断仍维持原置信度阈值，不把多个低置信度选项相加放行；接口错误不进入语义重判。已完成或待确认的历史消息不会自动重放，修正后重新发送本轮要求即可使用新判断。

项目任务类型由用户动作与代码状态机确定，不需要模型再次决定当前是生成还是审核。已移除剧本生成、剧本审核、分镜生成等调用点的旧辅助初筛，避免对截断章节重复判断。旧 `project_jev.py` 辅助接口仅供历史测试与评测，生产代码只复用其中的证据清理函数。

原文覆盖、剧情逻辑、邻镜衔接、手册要求、时长与模型能力仍由原审核和代码校验负责。JEV 的局部通过不等于整镜或整章审核通过，不直接批准作品或跳过校验。

## 判断边界与恢复

`jev_control.py` 负责模块、项目意图、局部审核和修复字段。接口失败、非法结果、证据过长或置信度不足时不转交其它模型决定。全自动保存成果并进入 `WAITING_USER`；检查配置或内容后点击“重新判断”继续原阶段。首页和项目普通对话给出待确认说明，不提交媒体任务；明确图片/视频模式的模块判断异常保存任务失败状态供重试。

单镜局部审核比较场景与动作的身份/服装/起点、场景与首帧、布局与首帧。合法的先坐后站、换手等不视为同时间矛盾。代码固定问题镜号与字段，修复仅合并允许字段。

单次控制证据上限 14000 字符。局部审核优先合并字段对，超长时拆成完整字段对，仍超长则待确认，不截断后批准。控制阈值为 `max(0.8, 管理页阈值)`，明确矛盾至少为 `max(0.85, 管理页阈值)`。首页交付路由保留原有偏向文本、谨慎触发媒体的阈值与参数继承规则。模型置信度不等于实测准确率。

成功控制判断保存到任务检查点，按证据、问题、模型、平台、阈值和凭据指纹区分。未变化的判断可复用；不保存明文密钥。用户的图片引用、草稿、参数和连续任务仍保存在原有会话状态中。
