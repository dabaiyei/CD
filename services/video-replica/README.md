# 本地视频复刻

独立入口 `/video-replicas`。使用固定版本 `@hypit/hypit@0.2.16`，不修改项目、章节、分镜或导演全自动状态。

## 安装

在此目录执行 `npm ci --ignore-scripts`。API/worker 所在环境需要 Node.js 22.15+、FFmpeg、FFprobe。
Hypit 在首次合成时准备自己固定版本的本地渲染器和 Chrome Headless Shell，需要联网下载。
本机已完成依赖准备。Windows 会把当前 Python 环境的 Scripts 目录加入子进程 PATH。

## 流程

1. 上传视频（最大 100MB、最长 180 秒），或输入 HTTP(S) 视频文件直链。
2. Hypit 读取媒体，本地 WhisperX 自动识别对白并对齐时间戳（默认中文，可选英文）；无音轨自动跳过。新分析使用 v3 全片阅读：先观察整片，记录叙事/视听系统与改编方案，再对疑问位置加密取样，按语义段落细读。每次最多4张带时间戳组图，不加载其它项目手册或全量 Skills。
3. 分批保存分析；时间轴须连续覆盖参考视频，失败只补未完成批次。
4. 用户编辑各片段提示词，选择现有视频平台、比例、分辨率、声音来源。
   工作台支持上传自有图片（单张 100MB）、搜索本人个人/项目资产、调用图片模型生成参考图；每张图可填写主体替换或服装等用途。
   每张图区分人物、场景、画风、已完成场景首帧，人物须指定原片替换对象，可勾选适用镜号。
   AI 生图可选择将已有参考图一并传入图片模型，完成后手动“加入参考”。添加图片不再关闭原视频动作参考。
   “保存方案与绑定”将编辑草稿存到服务端；“预览生成编排”显示每个生成段涵盖的镜号、时长、参考和能力限制。
5. 新任务使用 v2 编排：分析镜头与生成任务分离，相邻同场景、同参考的短镜头在模型时长范围内合并。
   可标记自然切镜或必须连续的动作；分析检查范围不决定生成任务边界。
   各生成段单独调用文本模型，结合实际图片绑定改写目标外观和局部动作时间轴，保存改写结果。
   full_reference 模型同时接收新人物图片和原片视频片段；不会再把带原人物的首帧一并塞入。
   仅支持首帧时，先用选定图片模型结合自定义人物与原片构图生成目标场景图，再传给视频模型。
   必须拆开的连续段等待前段完成，实际尾帧同时传给改编模型和视频模型；自然切镜没有此依赖。
   长度不足模型最短时长的片段按合法时长生成并保留完整结果，不硬截到原片长度；原音仅取对应区间并适配节奏。
6. 保存服务商任务 ID、原始结果和完成片段；查询失败或本地处理失败不会丢弃已完成媒体。
   单片段临时失败自动尝试最多 3 次，间隔 5/15 秒；仍失败则记录错误并继续其他片段。
   查询异常继续使用原平台任务 ID；平台明确失败或返回无效视频才开启新的生成尝试与幂等标识。
   全部片段完成后自动拼接；仍有缺失时显示具体片段编号，手动继续只补未完成部分。
7. 程序生成原生 SVML/SVS/SVRun 工程，Hypit 校验、渲染、导出 MP4；工作台提供预览与下载。
8. “制作工程”接入本地原生 Hypit Studio：真实时间轴、组件 Inspector、源文件编辑、预览、时间点反馈。API 通过短期、单工程会话转发；没有外部站点跳转，也不把 Node 端口开放给公网。参数/时间轴/反馈自动保存到服务端；源码使用原生编辑器保存按钮后同步。单机最多8个编辑器，闲置30分钟回收。
9. 可继续导入图片/B-roll视频/音乐/音效（单份100MB），让 AI 按需使用本地组件改编工程；不接受用户或模型提供的任意本机路径、Shell、JS/TS插件或外部媒体地址。AI 修改须通过原生 check；只返回更改的文件，其他源文件与媒体保持原样。
10. 字幕后期先识别实际成片音轨，再通过 Script + WhisperX SemanticTake + Caption Fine 做逐词对齐；中文/英文显式选择。无声或无可识别对白时不编造台词。原片转写不能直接当作新生成视频的字幕时钟。
11. 制作修改与重新导出为独立持久任务。导出只执行本地制作，不调用图像/视频模型；已完成素材不会重生成。支持下载含媒体、源文件、制作文档和许可证的完整工程包，包内不含模型 API Key。历史成功复刻的片段可恢复为原生工程。

## 制作工程与上下文

`BRIEF.md` 保存需求；`ANALYSIS.md` 保存全片理解；`TREATMENT.md` 保存改编决定；`TIMELINE.md` 保存时间点证据；`PROGRESS.md` 保存进度。`TRANSCRIPT.md` 保存实际成片对白，`FEEDBACK.json` 保留原生时间点反馈。

源文件固定为 `composition.svml`、`look.svs`、`render.svrun`，不在每次改动时堆叠新的同名版本文件。编辑使用内容修订校验，冲突返回409，不覆盖另一窗口的新修改。导出任务冻结当前工程和素材快照，成功成片保持可用。

AI 后期每次只查询用户所选领域的1–4个已安装组件，去除重复语法说明，不载入上游整套 Skill。原生 Studio 保留 Hypit 的视觉编辑能力；本系统继续负责账户、模型调用、参考图绑定、任务队列和恢复。当前没有把上游独立付费语音供应商、平台分享链接抓取或任意第三方代码插件纳入已有模型平台；这些能力不能标为已迁移。

本地 Web 代理与 Nginx 已包含 Studio WebSocket 转发。API 进程内保存短期会话，部署时 API 使用单进程或粘性会话；源码与素材的持久状态仍在数据库/对象存储，不依赖会话存活。浏览器重新打开工程会使用已保存状态。

制作素材支持上传图片、视频、音频，以及调用现有 TTS 模型平台生成配音。配音任务保存平台任务ID、原始音频和归一化音频，重复提交同一请求复用任务。AI 后期可将配音作为旁白或替换原声。字幕从实际成片音轨经本地 WhisperX 转写并语义对齐，使用原生 Caption Fine 渲染；不会平均分字假造时间。工程所用 Fonts Open 字体按官方固定版本自动准备。导出 ZIP 包含源文件、素材与无密钥的本地运行配置。

## 边界

- 转写结果随任务保存，后续分析失败直接复用；转写失败明确报错，可重试，不会悄悄丢弃对白。可关闭自动转写并手动填写台词，也可原样保留原片音轨。
- 原声音、生成声音、无声三选一，避免两份对白叠加。
- 直链入口不处理平台分享网页、登录或 DRM 视频。
- 原帧参考保留原人物的约束较强；大幅换人/换风格可关闭它，使用文字复刻。
- 不执行模型生成的脚本、Shell 或外部组件代码。允许编辑经路径、组件白名单与原生编译校验的声明式 SVML/SVS/SVRun；媒体必须来自本工程的授权素材。
- 操作按 tenant_id + user_id 隔离。记录使用现有持久任务表；清理任务记录会移除工作台条目，但不会删除媒体文件。
- 提交时校验参考图所有权和视频模型能力，保存当时的资产图片版本与用途快照；不会在后台悄悄换成资产的另一个版本。单首帧模型只接受一张参考图，多图需模型支持。
- 切换任务可查看当次方案；失败的分析显示已保存批次。编辑后可点击“保存方案与绑定”，刷新也能恢复。
- v2 请求冻结生成编排、图像版本与人物绑定。提示词、合成场景图、平台任务及已完成片段分别断点保存。
- 已提交的旧任务保持原编排继续，防止片段索引错配。需要使用新编排时返回对应分析，预览后创建新的复刻任务。
- 实际人物相似度、动作和连续性仍取决于所选供应商模型；不支持视频参考的模型会在预览明确提示降级能力。
- 内部模块当前不扣站内积分，模型供应商仍按实际调用计费。
- 独立节点需在 API 和 worker 同时可见的位置安装本目录依赖，不能仅安装在 Web 容器。

## 本地自动转写

API/worker 的 PATH 需包含 `uv`（可在 Python 环境执行 `python -m pip install uv`）。
预热前将 `HYPIT_STATE_HOME` 设置为项目根目录下 `runtime-data/hypit-speech` 的绝对路径（与 API 保持一致，避免 Windows 用户目录路径过长）。
在此目录执行：`node node_modules/@hypit/hypit/bin/hypit.mjs programs up --runtime transcription.runtime.json --endpoint whisperx.local --json`。
也可以直接提交分析任务，任务会自动启动服务并报告进度。首次需联网下载 Python 依赖、Whisper small 与中英文对齐模型；耗时取决于网络，后续复用本地缓存和常驻模型。
Windows 使用 API 当前 Python 解释器创建隔离环境，避免重复下载 Python；独立预热可设置 `UV_PYTHON` 指向 Python 3.10–3.13。
`transcription.runtime.json` 配置 CPU/int8、batch=4、并发=1；同一主机的多个 worker 通过操作系统文件锁排队，进程退出自动释放锁。
服务仅监听本机 8765，不向第三方上传音频。转写不做说话人身份猜测；缺失时间戳的内容标注未对齐。识别错误可通过补充台词纠正。
容器部署需安装相同 npm/uv/ffmpeg 依赖并预热模型，持久化 Hypit 与模型缓存；此配置面向单机本地 worker，不提供跨主机语音队列。
模型准备依赖 Hugging Face 和 PyTorch 模型下载站点的网络可达性；下载失败时需恢复网络后重新预热，不会降级成无对白分析。

若 Hugging Face 无法访问，在项目根目录运行 `python scripts/prepare_replica_speech.py`：
从 ModelScope 下载同名 Whisper small 和中文对齐模型，核对文件大小与 SHA256；英文对齐仍取自 PyTorch 官方站点。
下载支持断点续传，完成后再运行上述 `programs up` 命令验证并启动服务。
配置将模型固定保存在 `runtime-data/hypit-speech/models`，无需修改系统代理或关闭 TLS 校验。
此缓存也需要在 Docker 中持久化；脚本不改变 ASR 模型、语言或转写质量配置。
